# 运营后台使用手册

> 面向管理员/运营。后台地址：`https://<你的域名>/admin`，用 `ADMIN_KEY` 登录。
> 本手册覆盖每个功能怎么用，以及常见运营场景的操作步骤。

---

## 一、登录后台

1. 浏览器打开 `https://<域名>/admin`
2. 输入服务器 `.env` 里的 `ADMIN_KEY`
3. 进入后台，顶部可「刷新」「退出」

> 安全提醒：`ADMIN_KEY` 等同后台最高权限，务必保密。建议后续加 IP 白名单。

---

## 二、后台功能总览

顶部标签页共 9 个：

| 标签 | 作用 |
|---|---|
| **令牌** | 管理 API 令牌（sk-...），启停、配额、限速、模型白名单 |
| **用户** | 管理用户、余额充值、启停账号 |
| **渠道** | 配置上游模型（DeepSeek/Claude/Gemini/OpenAI 等）与 API Key 池 |
| **定价** | 设置每个模型的计费单价 |
| **请求日志** | 查看每一次调用明细，多维筛选、分页 |
| **兑换码** | 批量生成/作废/导出充值兑换码 |
| **订单** | 查看充值订单，手动补单 |
| **系统设置** | 热更新公告、站点名、注册开关等 |
| **审计** | 查看所有管理操作留痕 |

顶部 4 个数据卡片：活跃令牌、今日请求（含成功率）、今日消费、累计消费。

---

## 三、核心概念（先理解再操作）

- **credits（点数）**：内部计费单位。`1 USD = 1,000,000 credits`。给用户充值、模型定价都用它。
- **渠道（Channel）**：一个上游模型来源，含 `base_url` + 一批 API Key（多个即自动轮询池）+ 支持的模型。
- **令牌（Token）**：发给用户的 `sk-...`，归属某个用户，调用时扣该用户余额。
- **定价（Pricing）**：模型的单价（credits/1K tokens）。**未配价的模型不扣费**（免费）。
- **用户余额**：用户的 credits 池。调用前预扣冻结，完成后按实际用量结算。余额不足会返回 402。

## 四、常见运营场景

### 场景 1：新增一个模型渠道（如接入 DeepSeek）

1. 进「渠道」→「＋ 新建渠道」
2. 填写：
   - 名称：`deepseek`
   - 类型：`openai`（DeepSeek 是 OpenAI 兼容协议）
   - Base URL：`https://api.deepseek.com/v1`
   - API Keys：粘贴你的 key，**一行一个**（多个 key 会自动轮询、分摊额度、故障切换）
   - 模型：`deepseek-chat`、`deepseek-reasoner`（一行一个）
   - 分组：`default`；权重：`1`
3. 保存。渠道立即生效（路由缓存约 10 秒刷新）。

各模型的类型对照：
| 上游 | 类型 | Base URL 示例 |
|---|---|---|
| DeepSeek | `openai` | `https://api.deepseek.com/v1` |
| OpenAI / Codex | `openai` | `https://api.openai.com/v1` |
| Claude | `claude` | `https://api.anthropic.com` |
| Gemini | `gemini` | `https://generativelanguage.googleapis.com/v1beta` |
| OpenRouter | `openai` | `https://openrouter.ai/api/v1` |
| 通义千问 | `openai` | `https://dashscope.aliyuncs.com/compatible-mode/v1` |

> **API Key 池**：同一个渠道填多个 key，系统会加权轮询使用，某个 key 失败会自动换下一个；
> 连续失败达阈值会熔断该渠道，冷却后自动恢复（渠道列表的「失败」列可观察）。

### 场景 1.5：管理渠道的 API Key 池（v2.3）

渠道列表每行有「账号池」按钮，点开可以：
- **查看每个 key 的统计**：成功/失败次数、最近状态码（key 已脱敏，只显示掩码）
- **测试首个 / 全部 key**：发一条极小探测请求，立刻看到每个 key 是否可用、延迟多少、报什么错。
  用来快速定位"池子里哪个 key 挂了/欠费了"。测试不计费、不写用量。
- **单独停用/启用某个 key**：把失效的 key 停掉，路由会自动跳过它，不影响池里其他 key。
- **发现模型**：从上游拉取它支持的模型列表（仅 OpenAI 兼容渠道），复制到渠道的模型框即可。

> 排查建议：某渠道 502 变多时，先点「账号池 → 测试全部 key」，看是哪个 key 的问题，停用它即可。

### 场景 2：给模型配置价格

1. 进「定价」→「＋ 新建定价」
2. 填写：
   - 模型：`deepseek-chat`
   - 分组：`default`
   - 输入价 / 输出价：credits per 1K tokens
3. 换算参考：DeepSeek 约 ¥1/百万输入、¥2/百万输出 → 输入价填 `139`、输出价 `278`
   （1 元 ≈ 138,888 credits，除以 1000 得每 1K 的价）
4. 倍率：默认 `1.0`。想对某分组用户加价可调高。

> 不配价 = 该模型免费调用。想让某模型免费引流可故意不配价。

### 场景 3：给用户充值

**方式 A（后台直接改余额）**：
1. 进「用户」→ 找到用户 →「充值」
2. 填 credits 金额（可负数做扣减），确认。会记一条账单流水。

**方式 B（发兑换码，适合批量/线下）**：见场景 4。

### 场景 4：批量生成兑换码

1. 进「兑换码」→「＋ 批量生成」
2. 填单张面额（credits）、数量（1-1000）、批次标记（如 `2026-promo`）
3. 生成后**自动复制到剪贴板**，也可用「导出未用(CSV)」下载
4. 把兑换码发给用户，用户在前台「充值」页输入即到账
5. 需要作废未发出的码：列表里点「作废」，或按批次批量作废

### 场景 5：为用户/团队创建 API 令牌

1. 进「令牌」→「＋ 新建令牌」
2. 选择归属用户，可选设置：
   - 配额 tokens（该令牌能用的 token 上限，独立于余额）
   - 有效天数、限速 RPM、允许模型（白名单，逗号分隔）
3. 保存后 key **自动复制**，发给用户
4. 用户在客户端填：Base URL = `https://<域名>/v1`，API Key = 这个 sk-...

### 场景 6：排查用户报错

1. 进「请求日志」
2. 用筛选栏按「令牌名/模型/渠道/状态码」定位，或勾「仅错误」
3. 看「错误」列的上游返回信息。常见：
   - `401`：令牌无效/停用/过期
   - `402`：用户余额不足 → 提醒充值
   - `429`：触发限速或配额用尽
   - `404`：模型无可用渠道 → 检查渠道配置
   - `502`：所有上游失败 → 看渠道 key 是否有效、余额是否欠费

### 场景 7：手动补单（用户已付款但订单未自动确认）

1. 进「订单」→ 找到 `pending` 订单
2. 核实用户确实已付款后，点「补单」
3. 系统幂等入账（不会重复加钱），并记审计日志

### 场景 8：发布公告

1. 进「系统设置」→ 填「首页公告」→ 保存
2. 公告立即显示在用户门户/控制台顶部（热更新，无需重启）
3. 清空公告即隐藏

### 场景 9：临时关闭注册

1. 进「系统设置」→「开放注册」选「否」→ 保存

### 场景 10：看经营数据（数据分析页，v2.4）

进「数据分析」，右上角选区间（7/30/90 天）：
- **收入概览**：充值收入、消费、退款、净收入（净收入 = 充值 + 正向调整 − 退款）。
- **消耗排行**：模型/用户/渠道 Top 榜，按费用排序，快速看谁最烧钱、哪个模型最热。
- **按天趋势**：每天的请求数、tokens、消费。
- **告警**：熔断的渠道、低余额用户一眼可见。

### 场景 11：批量操作（v2.4）

在「令牌」页勾选多个令牌（或表头全选），可**批量启用 / 停用 / 删除**（如封禁一批异常令牌）。

其他批量能力（当前通过 API）：
- 批量给一组用户充值：`POST /admin/users/batch-topup {user_ids, amount}`
- 直接给某用户发放充值（客服补偿）：`POST /admin/redemption/grant {user_id, amount, note}`

所有批量/发放操作都记入「审计」页。

## 五、部署级配置（在服务器 .env，需重启生效）

以下不在后台改，属于部署配置（`deploy/.env`）：

| 配置 | 说明 |
|---|---|
| `EMAIL_AUTH_ENABLED` | 是否开放邮箱密码登录（默认关，仅 OAuth） |
| `OAUTH_PROVIDERS` | GitHub/Google 等第三方登录配置 |
| `PAYMENT_PROVIDERS` | 支付渠道（加密货币/易支付）配置 |
| `USD_CNY_RATE` | 人民币汇率 |
| `SITE_DOMAIN` | 站点域名 |

改完执行：`ssh 服务器 'cd /opt/llm_api/deploy && docker compose -f docker-compose.prod.yml up -d app'`

## 六、日常巡检建议

- 每天扫一眼概览卡片：今日请求量、成功率、消费是否正常。
- 「请求日志」勾「仅错误」看有无异常集中（某渠道大量 502 = 该上游挂了）。
- 「渠道」列表看「失败」计数与状态，熔断的渠道排查 key。
- 「审计」定期查有无异常管理操作。

## 七、术语速查

| 词 | 含义 |
|---|---|
| credits | 内部点数，1 USD = 100 万 |
| RPM | 每分钟请求数限制 |
| 熔断 | 渠道连续失败被自动停用，冷却后恢复 |
| 预扣/结算 | 调用前冻结预估费用，完成后按实际扣费退差额 |
| 分组 | 用户/渠道/定价的分类，可做差异化定价与路由 |
