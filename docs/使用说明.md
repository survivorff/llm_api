# llm_api 使用说明（v2.0）

一个 OpenAI 兼容的 LLM 网关 / 中转平台：多协议、多渠道、按量计费、充值、
用户自助、后台运营。本文覆盖本地体验与服务器部署两种场景。

---

## 一、5 分钟本地体验（SQLite，无需 Docker）

```bash
cd llm_api
cp .env.example .env      # 至少改 ADMIN_KEY / SESSION_SECRET / CRYPTO_SECRET
bash run.sh               # 自动建 venv、装依赖、建表、启动
```

启动后（默认 http://127.0.0.1:8080）：

| 入口 | 地址 | 说明 |
|------|------|------|
| 用户门户 | http://127.0.0.1:8080/ | 注册/登录、令牌、充值、账单（中/英） |
| 管理后台 | http://127.0.0.1:8080/admin | 用 `ADMIN_KEY` 登录 |
| 健康检查 | http://127.0.0.1:8080/healthz | |
| 指标 | http://127.0.0.1:8080/metrics | Prometheus 格式 |

> 提示：若本机开了系统代理导致访问 127.0.0.1 异常，curl 加 `--noproxy '*'`，
> 或在 `.env` 设 `HTTP_TRUST_ENV=false`（仅本地）。

## 二、配置渠道 → 定价 → 分发令牌（管理员）

1. 打开 `/admin`，输入 `ADMIN_KEY`。
2. **渠道**页新建上游，例如 DeepSeek：
   - 类型 `openai`、base_url `https://api.deepseek.com/v1`
   - 填真实 API key、模型 `deepseek-chat`
   - Claude 上游选 `claude` 类型，Gemini 选 `gemini` 类型（自动协议互转）
3. **定价**页给模型配价（credits/1K tokens，`1 USD = 1,000,000 credits`）。不配价则不计费。
4. **用户**页建用户并充值余额，或让用户在门户自助注册。
5. **令牌**页为用户生成 `sk-...`，或用户在门户自助创建。

---

## 三、调用网关（用户 / 客户端）

三要素：
- Base URL：`http://<host>:8080/v1`
- API Key：门户或后台拿到的 `sk-...`
- Model：`deepseek-chat` / `claude-3-5-sonnet` / `gemini-1.5-pro` 等

```bash
curl http://127.0.0.1:8080/v1/chat/completions \
  -H "Authorization: Bearer sk-你的令牌" \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-chat","messages":[{"role":"user","content":"你好"}]}'
```

支持端点：
- `POST /v1/chat/completions`（流式/非流式）
- `POST /v1/embeddings`
- `POST /v1/images/generations`
- `POST /v1/messages`（Anthropic 原生入口）
- `GET  /v1/models`、`GET /v1/me`

在 Cursor / Cline / Aider 里：Provider 选 OpenAI Compatible，填 Base URL + API Key + 模型名。

## 四、充值

用户在门户「充值」页：
- **兑换码**：管理员在 `/admin/redemption/generate` 批量生成后发放。
- **在线支付**：需在 `.env` 的 `PAYMENT_PROVIDERS` 配置易支付（微信/支付宝）或加密货币（USDT-TRC20）。

配置示例见 `docs/design/v1.2-PAYMENTS.md`。

## 五、服务器部署（Docker + Postgres + Redis）

```bash
cp .env.example .env
# 必改：ADMIN_KEY / SESSION_SECRET / CRYPTO_SECRET（用 openssl rand -hex 32 生成）
# DATABASE_URL 指向 Postgres（compose 已内置），REDIS_URL 指向 Redis
docker compose up -d --build
```

- 容器启动自动跑 `alembic upgrade head` 迁移。
- compose 带健康检查，Postgres 就绪后再起 app。
- 多实例：加大 `WEB_CONCURRENCY` 或起多个 app 副本（无状态，配 Redis 后限流/会话一致）。

### 安全红线（上线必做）
- `ADMIN_KEY` / `SESSION_SECRET` / `CRYPTO_SECRET` 必须为强随机值。
- 前置 Nginx/Caddy 做 TLS + 限流；`/admin` 加 IP 白名单。
- 阅读并落实 `docs/design/COMPLIANCE.md` 的合规义务。

## 六、可观测与运营

- **指标**：`GET /metrics`（Prometheus 抓取），含请求数/错误/token/延迟直方图。
- **审计**：`GET /admin/audit`，管理操作留痕，超期自动清理（`AUDIT_RETENTION_DAYS`）。
- **公告/设置热更新**：`PUT /admin/settings`，无需重启，门户首页展示公告。
